# Design

## Context

见 proposal.md。当前样式由 tokens、reference、shell 顺序加载，reference 内含原型基础、960×600 适配和深色覆盖，shell 内含业务补丁。AppLayout 使用 CSS Modules；ReadingPage.module.css 未使用。多个页面通过共享 UI 和业务组件复用视觉。

## Goals / Non-Goals

**Goals:** 以普通 CSS 和显式前缀建立清晰的归属，保留选择器的具体程度、原有声明及每个归属内的覆盖顺序，检查拆分后的级联效果。

**Non-Goals:** 不重设计，不调整窗口、接口、数据和权限，不引入 CSS-in-JS、CSS 层级框架或新依赖。

## Decisions

- 页面样式与 Page.tsx 同目录；独立复用的 Player、GameCard、SteamDetail、截图轮播、导入弹窗、ReaderImage 和公共 UI 有自己的 CSS。六个业务前缀对应 feature；应用壳为 app；公共 UI 与工具类为 ui。状态类也加前缀，并在所属组件选择器中限定。
- 全局保留 tokens.css、base.css、utilities.css 和 shell.css。base 负责根节点与原生元素基础规则，utilities 负责共享排版、图片、徽标、进度和表单基础视觉，shell 只负责桌面环境材质。公共按钮类同样可用于 Link。
- 样式入口先加载全局规则，再加载公共组件、应用布局、业务组件和页面；各归属内部维持原来规则顺序。跨组件的页面布局覆盖放页面文件，明暗主题和 960×600 适配就近维护。播放器控件在首页样式后加载，保留复用控件优先的尺寸；空状态最后加载，保留其标题/图标对容器通用正文样式的覆盖。入口注释说明这两个级联顺序。
- 普通 CSS 的导入仍是全局生效；通过类名前缀避免冲突，不增加页面根节点改变布局。动态阅读字号、缩放和预览透明度继续使用内联样式。

## Risks / Trade-offs

- [拆分改变加载顺序] → 迁移前后比较八个路由的明暗主题计算样式与尺寸，更新并执行现有 DOM 接线回归；额外检查选择器与声明迁移完整性。
- [动态类名或测试选择器遗漏] → 检查 className 表达式、漫画模式插值、Button variant 映射及 DOM 查询，类型检查和构建验证。
- [浏览器没有真实数据及原生材质] → 使用现有 fixture 回归首页/Steam 正常数据、详情及轮播；如无法进行真实桌面材质验收，在交付中明确，浏览器结果不作为 Windows 原生效果证据。

## Migration Plan

记录浏览器基线后同步迁移 CSS、JSX 类名与测试选择器，删除集中参考文件及 CSS Modules，更新规范与 UI 说明。验证后归档并提交一次相关改动；回退可撤销该本地 commit。

## Validation

- 一次性静态检查：215 个旧类名映射为 215 个唯一带前缀类名；原有 897 条独立选择器规则（包括媒体查询和动画）及其声明完整保留，35 个 CSS 文件在入口中登记，无重复导入。CSS 格式化的数值和属性引号差异归一化后比较。
- 浏览器预览：八个路由的明暗主题共 16 种未接入/未选择状态，迁移前后主要计算样式和全部元素尺寸一致。
- 隔离 fixture 浏览器：共 36 种明暗主题场景，比较全部静态计算样式和尺寸，差异为零。覆盖正常首页摘要、歌曲/歌单/歌词、Steam 精选/特惠/搜索/详情与截图轮播、帖子及图片弹窗、本地书架、小说滚动/分页、漫画单页/连续、账号弹窗、导入选择与预览、小说排版、在线作品详情和设置。轮播淡入动画的瞬时 opacity 不参与比较，动画声明仍在完整性检查中验证。
- 测试 fixture 与一次性验证脚本仅位于被忽略的 `.build-tmp/styles/`；未注册正式服务、不提交、不写入用户阅读/设置数据。测试设置使用独立内存存储。
- 未运行真实 Tauri/Windows 桌面材质、原生文件选择和真实数据源验收。没有修改 Rust、Tauri 配置、服务或平台行为，浏览器验证不作为原生效果证据。
