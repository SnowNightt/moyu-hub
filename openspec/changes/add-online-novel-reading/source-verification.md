- 本轮临时探针和完整原生响应摘要保留在本地忽略目录，不是已加入仓库的正式脚本/测试入口。本文记录可独立复核的请求契约、样本和结果，不依赖读取整部小说正文。报告仅记录正文长度、字段和必要元数据，不收录正文全文；编码 URL 参数在摘要中遮蔽。

## 笔趣阁：任务 1.1 通过

### 请求契约

从用户给定站点公开的 [read.js](https://www.bqg616.cc/js/read.js?v=1.2606) 和 [common.js](https://www.bqg616.cc/js/common.js?v=1.2606) 静态检查必要协议。字符串表只按常量和编码规则解析，不使用 eval、Function、vm 或执行下载的来源代码。

- 实际主 API 为 `https://apibi.cc`。脚本还列出 `apiqu.cc`、`apige.cc`，本轮没有请求或验证这两个备选主机，不能直接认为它们也可启用。
- 搜索：`GET /api/search?q=<UTF-8 百分号编码的书名或作者>`；响应包含 `data` 数组。按站点脚本每 15 条切片分页，无额外分页请求；本轮确认返回完整该次结果数组和可切片数量，没有验收尚未实现的翻页 UI。
- 详情：`GET /api/book?token=<编码参数>`，参数 `{ "id": <作品 ID> }`。
- 目录：`GET /api/booklist?token=<编码参数>`，参数 `{ "id": <目录 ID> }`，响应 `{ "list": [章节标题, ...] }`。
- 正文：`GET /api/chapter?token=<编码参数>`，参数 `{ "id": <作品 ID>, "chapterid": <目录内一基序号> }`。
- 参数编码：将紧凑 JSON 作 UTF-8 输入；取公开字符串 `book@token.html` 的 MD5 十六进制表示，前 16 个 ASCII 字符作 IV、后 16 个 ASCII 字符作 AES-128 key，以 CBC / PKCS7 加密，Base64 后百分号编码。这里的 token 是网页公开的请求参数编码，不是用户账号凭据。本轮使用独立本地实现构造，没有执行 CryptoJS 或来源混淆脚本。
- API 声明 `Content-Type: text/html; charset=utf-8`，实际体为 JSON；读取必须依协议验证内容，不能仅按 MIME 判定为网页。
- 详情字段包括 `id/title/author/intro/full/lastupdate/lastchapterid/dirid`。本轮三个样本的作品 ID 与 dirid 相同，仍需分开保存，不能推广为所有作品恒等。
- 正文字段包括 `id/chapterid/dirid/title/author/chaptername/cs/ck/txt/time/md5`；`txt` 为可读文本。目录序号不是永久章节身份，稳定匹配仍是后续任务。
- 封面：`https://www.bqg616.cc/bookimg/<floor(id/1000)>/<id>.jpg`，本轮三张均完整 GET 并成功解码。

前次直接使用主站普通 `id/chapterid` 不能构成正确正文契约。本轮 Node 对照请求 `https://apibi.cc/api/chapter?id=583&chapterid=1` 仍为 403/空体，正确 token 请求在同一主 API 和真实 Tauri 客户端为 200。原普通请求缺少公开网页要求的参数编码；未对主站 403 的底层策略作额外推断。

| 作品       | 作者         | 作品 ID | 搜索结果数量：书名 / 作者 | 目录章数 | 第 1/2/3 章文字长度 | 结果       |

结论仅为请求协议通过；当前在线 tag、分页 UI、入库、进度、书签、缓存及正常退出恢复仍未实施。

## 神凑：任务 1.2 阻塞

### 公开搜索表单与实际响应

现阶段读取主机为 `https://www.wowenku.com`。页面表单为 `POST /modules/article/search.php`，字段 `searchtype`、`searchkey`，提交按钮字段 `t_btnsearch`；页面提供 `articlename`（书名）、`author`（作者）、`keywords`（别名）。

真实原生表单请求使用 `application/x-www-form-urlencoded`，按照 GBK 编码传递：

| 查询       | 表单主体关键值                                  | 第一轮原生 | 请求头复核原生 |
| ---------- | ----------------------------------------------- | ---------- | -------------- |
| 书名“败犬” | `searchtype=articlename&searchkey=%B0%DC%C8%AE` | 403        | 403            |
| 作者“雨森” | `searchtype=author&searchkey=%D3%EA%C9%AD`      | 403        | 403            |

四次搜索响应都包含 `cf-mitigated: challenge`，HTML 标题为 `Just a moment...`，识别到 `challenge-platform/cf-chl` 等验证页标记。验证页不是零结果，也没有到达可验证的正常搜索数据。因此不能认为搜索编码、搜索结果解析或翻页已通过。

请求头复核仅在临时探针编译时启用 HTTP 插件的 `unsafe-headers` feature，以实际 WebView2 User-Agent、站点 Origin、Referer 和 Accept 重现公开表单请求；先读取文库页建立匿名原生会话，仍被拦截。未修改项目 Cargo.toml、正式 capability/CSP，不读取用户浏览器 cookie，不执行验证页面脚本或解决验证码。

同一公开端点的 Node GET 参数兼容性诊断也返回 403 / `cf-mitigated: challenge`；这是辅助对照，不算 Tauri 验收，不据此增加新的正式请求路径或降级入口。

匿名文库页 GET 返回 200，声明 gb2312；目录与正文页声明 GBK，以 GBK 解码可以正确提取中文。这里只证明可读取的样本，不是应用的粘贴链接入口，也不能替代应用内搜索。
