# Design

## Context

动机与功能范围见 [proposal.md](proposal.md)。已确认行为分别维护在 [找书](specs/online-novel-discovery/spec.md)、[阅读](specs/online-novel-reading/spec.md)、[书架与历史](specs/online-reader-library/spec.md)、[缓存](specs/online-reading-cache/spec.md) 四份规格中；这里定义实现边界，不把历史计划整体作为本次需求。

## Goals / Non-Goals

**Goals:**

- 以固定两站适配器将远端内容规范化为既有小说内容块，复用当前阅读器与唯一 SQLite 书库。
- 将作品/章节身份、实际读取定位、书架可见性、历史可见性和可重建缓存分开，防止来源更新导致错章与数据丢失。
- 在原生请求、缓存和进度写入边界实现取消、有限重试与原子发布，并保持已确认的用户流程。
- 以先验证来源、再实现完整链路的顺序减少对不可用协议的无效开发；未通过来源门槛不得改变规格来宣称完成。

**Non-Goals:**

- 不另建浏览器嵌入阅读器、Vite 生产代理、常驻爬虫、通用可执行脚本书源或第二个书库数据库。
- 不下载执行来源 JavaScript，不假定浏览器与原生请求共用 cookie，不增加站点账号/验证码交互。
- 不修改本地作品移除规则、原有本地进度算法、0001/0002 已发布迁移或既有 Windows 窗口材质。
- 用户层面明确排除的入口与功能以 proposal 和规格为准；本轮仅规划，工程文档现状等到实现后按矩阵同步。

## Decisions

### 1. 固定来源、先验证实际原生协议

使用固定 `bqg`、`shencou` 来源 ID；tag 与来源一一映射。来源 ID 不随域名迁移改变。初始网文来源为用户提供的 bqg616；神凑历史入口及历史新域名 wowenku 仅用于验证线索。应用中不提供原站、URL 粘贴或替代来源入口。

在任何完整 UI、迁移实施前，P0 必须取得两站免账号登录的实际 Tauri 搜索、详情、目录、正文成功响应，记录书名/作者查询、分页、目录身份、正文格式、编码、所需域名/重定向和图片完整 GET/解码。每站指定至少三部验收作品。结果写入本变更的 `source-verification.md`（实施时生成），不得只记录浏览器可读或 HEAD 200。

P0 若失败：保留具体失败证据，将相应任务保持未完成，停止来源启用和依赖该协议的完整实现；可完成定位明确的其他验证，但不得接入演示服务、跳转原站或以单站宣布完成。任何改变免登录或两站交付门槛的方案需要新的用户决策。

替代方案：使用浏览器嵌入、用户 cookie 或链接阅读更容易跨过部分入口，但违反已确认边界；通用书源框架增加无本次需求依据的运行层。均不采用。

### 2. provider、仓库与平台分工

页面通过模块契约消费数据，来源 URL、解析与编码不进入页面。固定 provider 的最低契约为 search、detail、chapters、chapter、resolveAsset；作品引用为 providerId + remoteWorkId，章节引用另带实际远端读取定位。搜索结果是远端摘要，不冒充已经入库的 LibraryItem。

TypeScript 模块适配器负责协议、响应校验和 HTML/JSON 规范化；平台 HTTP 提供原生请求、字节/文本读取与取消；Rust reader 负责元数据事务、受控缓存、资源下载/解码与二进制 IPC。正文按既有 ContentBlock 分块，插图登记为 resourceId，页面继续取得受控 Blob URL。

扩展 ReaderRepository 提供以下在线操作，同时保留本地 content/asset、进度串行写入和 flush：

| 操作             | 责任                                                  |
| ---------------- | ----------------------------------------------------- |
| ensureOnlineItem | 幂等登记作品身份和可信元数据；默认不入书架、不写历史  |
| setInShelf       | 在线书架可见性切换；本地原有 remove 单独保留          |
| refreshChapters  | 获取并验证完整目录，在事务内发布匹配结果              |
| prepareChapter   | 命中缓存或请求正文，准备 chunks、资源和定位所需元数据 |
| reloadChapter    | 用户显式重新获取当前章，发布完整版本前保留旧内容      |
| recentReading    | 直接返回可见历史及作品摘要，包含未入书架作品          |

以按 source 分发的统一仓库组合两站与现有 Rust 本地阅读，不建立第二套在线阅读页或 Zustand 业务持久化仓库。该契约是本次设计，不表示已存在实现；具体类型在实施时保持运行时校验。

替代方案：页面直接取第三方地址或自行操作 SQL，容易让入库、历史和缓存各自产生不同身份；独立在线库无法自然保留书架与首页的唯一位置。均不采用。

### 3. 请求、编码、来源解析和权限

平台 HTTP 增加明确 JSON/字节响应能力，以及真实 GET/POST、表单 body 和必要请求头。保持既有 Steam 请求和错误文本的调用兼容，通过阅读专用包装映射网络、超时、限流、验证拦截、登录限制与解析错误。初始沿用现有超时和一次有限网络/网关错误重试；验证拦截、确定的解析错误不反复重试，取消不报来源故障。

笔趣阁优先使用经 P0 验证的 JSON 协议；参数编码只实现必要本地纯函数，不运行远端混淆脚本。历史搜索返回数组、前端按 15 条切片：若原生复核一致，按当前查询缓存数组后本地分页；来源改变为服务端分页则由同一分页契约表达，不编造完整站内总数。

神凑读取原始字节后按 HTTP/页面编码声明解码，处理 GBK/gb2312 与对应表单编码；编码能力在实际 WebView/原生流程验证。HTML 通过 DOM 解析提取正文范围和有序目录；历史 `.zjbox`、`.ttname h2`、`.zjlist4 a` 与 `<!--go-->` 只是定位线索，结构需复核。规范化时去掉广告占位、导航、表单、脚本和事件属性，保留内容范围内的文字、注释和图片。

所有封面和插图经原生受限请求与资源缓存，不把任意来源 URL 直接填入 DOM。沿用已有尺寸、体积和解码预算检查，返回真实资源尺寸，避免小说插图一律使用 800×1200 占位。

前端 HTTP capability 按 P0 确认的 API/页面主机和路径增补。Rust 图片下载必须独立验证来源、主机、协议、重定向和体积，自定义命令不受前端插件 scope 自动约束；可复用 HTTP 插件的 Rust HTTP 能力，是否新增依赖以本地实际 API 和 P0 为准。对历史 HTTP 外部图片先验证 HTTPS；确需 HTTP 时仅允许确认的图片主机/路径，不放宽 TLS 校验或全域权限。正文和图片均经原生/Blob 路径，尽量沿用 self/blob CSP，禁止引入 frame 或远端 script。

替代方案：默认 UTF-8 文本、正则抓整页、仅允许主站图片、通配 HTTP/CSP 都无法满足已识别的编码、跨主机插图或安全边界，不采用。

### 4. 统一数据模型和稳定定位

新增 `0003_reader_online.sql` 并注册迁移。library_items 增加 source、provider_id、remote_work_id、in_shelf；本地旧记录 source=local、in_shelf=1，在线记录 format=online，本地源文件字段可为空且按来源设置 CHECK。本地 format+fingerprint 与在线 provider_id+remote_work_id 分别唯一；本地旧 UUID 和 JSON 原样保留，读取时由结构化身份字段统一投影。

在线作品使用应用 UUID。作品标题、域名和书架状态均不参与身份；并发直接阅读/加入书架由唯一约束和事务返回同一作品。章节保留应用内稳定 ID、有效状态、目录顺序、可选卷信息、实际远端读取定位、目录版本和内容版本；图文资源使用稳定受控 ID，URL 与文件名分离。

神凑优先采用实际稳定远端章节 ID。笔趣阁历史目录只有标题数组，chapterid 为序号，不当作永久身份：

1. 尾部追加且旧目录为前缀时保留旧映射。
2. 其他变化按有序标题、相邻内容和已验证证据匹配；有可靠独立 ID 或内容证据时才支持改名匹配。
3. 重复标题、删除或证据不足保留旧章节及定位，标记不可可靠恢复，提示选章；不猜测标题相同就必为同章。
4. 远端读取序号与应用内 ID 分开，取正文时核对目录版本及返回章名，防止刷新与请求间的序号竞争。

目录全部成功获取和校验后再事务提交，刷新唯一 ordinal 时先解除事务内顺序冲突再重排；不再有效的旧章节保留为 inactive 供旧位置解释，正常目录不展示它们。失败不发布部分目录。

在线 ReadingProgress/Bookmark 增加可兼容读取的定位版本和内容版本；保留 blockId、UTF-16 offset、chunk 与位置。不强制改写本地旧定位。当前会话持有固定正文版本；恢复先匹配可靠章节，再匹配同版本锚点或能够证实对应的新锚点，无法可靠恢复时停止自动位置采集并提示。不能使用旧序号或比例自动宣布正文修订后的恢复成功。

替代方案：由章节序号/标题生成全局 ID 或刷新时删除全部进度会导致错章和数据损失；无证据的模糊匹配会掩盖错误。均不采用。

### 5. 阅读准备、历史写入与错误状态

打开详情不产生阅读历史。直接阅读先 ensureOnlineItem，再读取持久化元数据和位置，检查目录，prepare 目标章节的正文/资源，完成恢复后才开启用户阅读位置采集。目录检查失败但旧目录和目标缓存有效时允许继续；目标无法恢复时进入明确的选章状态。

ReadingPage 不再启动时读取整书图片资源，按当前章准备 chunks 和资源尺寸；以现有内容块、滚动/分页和排版状态渲染。ReaderImage 继续按生命周期释放 Blob URL，补单图重试和可见尺寸；纯插图章失败不等同成功空章。章节预取只更新缓存，不调用 saveProgress。

进度写入沿用串行队列、约 800ms 的现有合并节奏和退出 flush，但页面必须区分成功、失败及尚未保存；失败保持待写入位置并提供重试，不将旧失败或旧会话回写覆盖更晚位置。首次内容展示可在已登记元数据且缓存写入失败时使用受限内存，独立说明离线缓存未成功；数据库不可写则明确位置未保存。

首页改用 recentReading，以 history_visible 和 last_read_at 排序并获取作品摘要，最终仍只显示两条；in_shelf 不参与历史可见性判断。setInShelf 不更新 last_read_at，hideHistory 不删 position/bookmarks，只有实际阅读成功保存位置后恢复可见。

替代方案：把所有入库作品视为书架、详情打开即写历史、入库成功即显示已保存，均无法满足用户区分实际阅读、书架与保存失败的约定。

### 6. 导航与在线百分比

在线列表采用 Router 管理来源 tag、已提交关键词和页序；详情引用带 providerId 与 remoteWorkId，避免不同来源 workId 冲突。列表位置和结果快照保留在受控应用导航状态/当前查询缓存中。切换 tag 同时清关键词、页码、结果和旧请求；本地书架 filterBar 保留现有分类，不共享在线 tag 定义。

阅读入口携带受控内部 returnContext，从详情、书架、历史、首页分别返回原入口。正常导航回详情后关闭继续恢复搜索条件、页序和滚动。来源上下文缺失的深链默认返回该在线作品详情；首次在线页默认网文且未搜索，作为实现默认值，不增加设置或跨启动搜索恢复需求。返回状态只接受应用内部已登记路由。

在线全书进度采用 `(当前有效章的零基顺序 + 章内位置) / 有效章节数`，分卷标题、inactive 章节不计数。章内位置限定在 0–1，显示百分比按既有方式取整。无有效目录或定位待用户处理时不伪造已恢复的百分比。本地继续沿用按内容长度计算。书架、历史、首页和阅读页使用同一纯计算函数，目录新增后重新计算，位置不变；按用户明确要求不显示“估算”。

替代方案：全书字数加权要求预先获取整书或可靠全量字数，与按章读取不相容；沿用当前“找不到则第一章”和固定返回书架会破坏已确认上下文。

### 7. 缓存发布、预算和并发清理

在线内容独立放在 `app_cache_dir/reader/online/<itemUuid>/<chapterUuid>/<contentVersion>/`，封面采用同一 online 根内的受控资源路径，与现有本地 reader 缓存和托管原件分开。SQLite 保存作品/目录/定位及必要内容版本摘要，业务元数据不随缓存淘汰。在线预算统计全部正文、封面和插图，不混用 Steam 或本地生成图片预算。

缓存按资源大小和最近实际使用记录淘汰；当前会话正文版本及章节资源受保护。预取最多一个下一章，切章/切书/退出时取消旧预取，不递归扩展；预算紧张优先停止预取并清其他较久未使用内容。调低额度先淘汰非当前缓存；当前受保护内容单独超过新额度时暂停新增缓存和预取，显示真实占用，待离开该章后再恢复到上限。单次新内容大于可用额度时不静默扩大预算，可受限内存展示并提示未缓存。

正文/目录规范化之后计算版本哈希（不含易过期的 URL 签名参数）。缓存先临时文件完整写入、校验、原子更名，再发布数据库 ready 指针；发布失败不能把新文件视为成功。显式 reloadChapter 在新版本成功发布前不删除旧版本，缓存提交失败保留旧正文。目录更新只变目录和读取映射，不自动重取已缓存正文。

clearCache 增加缓存代次，取消预取和旧写入；下载/解析/写入提交前都核对代次与会话。清除可重建内容和缓存状态，不删除持久化的作品、目录、定位、书签、历史、必要定位版本摘要或本地托管原件。旧任务不得在清理后回填；当前已显示内容可短暂保留在会话内存，但不再宣称磁盘可离线读取。缓存文件缺失或损坏按未缓存处理，不返回空成功。

新增 onlineReaderCacheLimitMB 的默认值、五个允许值、校验、设置版本迁移和串行持久化；复用现有“缓存已用/清理缓存”入口，必要时显示在线实际占用。既有 comicCacheLimitMB 值及本地淘汰行为保留。

替代方案：只给插图限额会让正文无限增长，永久保存所有已读内容无容量边界，清目录但不停止旧请求会立刻回填，均不采用。

### 8. 验证与完成证据

新增可离线执行的来源解析、导航、目录身份、内容版本/定位、在线缓存和竞争、迁移、首页未入书架及设置用例；固定样本仅保留必要结构或生成内容，不依赖公网站点持续可达。根据实际改动定向运行阅读、设置、HTTP 和受影响 Steam 回归、TypeScript、Rust 检查，不默认全量测试。

真实验收分别记录公网原生请求、Windows 桌面开发版与发布 NSIS 安装版，发布时关闭 Vite 开发服务器。每来源至少三部作品完成搜索/作者查询/翻页/详情/任意章/前后章/书签/书架/历史/首页/正常退出重启流程；网文含连载长目录，轻小说含分卷、特典、插图完整下载解码。异常注入覆盖所有规格场景，用户界面 960×600 明暗、滚动/分页和排版均可操作。记录长目录和长章的首次可读时间、内存、取消与连续切换表现，不预先宣称具体性能数值达标。

实施完成后在本变更的 `verification.md` 记录样本、命令、通过数/总数、环境和未验证项；这是后续任务，当前文件不创建成功验收记录。按更新矩阵同步工程架构、测试指南，最后由 apply/归档流程同步主规格，本轮不提前归档。

## Risks / Trade-offs

- [两站协议或防护不支持当前免账号登录原生请求] → P0 先验证；失败保持明确阻塞证据，不改变两站完成门槛，不自动采用 WebView、登录或验证码方案。
- [笔趣阁目录序号变化导致错章] → 快照、稳定内部身份、严格有序匹配和章名核对；歧义交给用户重新定位，不凭名称强行匹配。
- [神凑 GBK、模板或外部图片地址改变] → 字节解码与结构/验证页面校验，按经证实的来源和图片域名请求，图片局部错误不阻断文字。
- [免登录读取不等于已明确来源使用条件] → P0 记录公开接口/页面条件与访问限制；条件未明确不声明来源验证完成，不在规划中作授权结论。
- [目录或正文替换覆盖旧定位] → 会话固定正文版本，完整快照/文件成功才发布，恢复失败不采集新位置；旧定位保留到用户明确选择。
- [缓存上限与当前章保护冲突] → 暂停新增缓存/预取，保护当前会话，调低上限产生的受保护占用在离开当前章后淘汰，并显示实际占用而非伪造限额内数值。
- [缓存/磁盘失败或应用中断留下不一致] → 有限内存与分离错误提示、临时文件/ready 指针、实际文件校验和受控孤立文件清理，保留最后成功保存的数据。
- [新迁移影响既有本地文件和进度] → 非空四格式旧库事务迁移、失败回滚和外键检查；不改已发布迁移、不清原件。
- [共享 HTTP 扩展损伤 Steam] → 保留既有调用兼容并运行受影响 HTTP/Steam 定向测试，不让来源错误文案泄漏到其他模块。
- [全书百分比按章节数量计算而非真实字数] → 内部计算保持一致并随目录变更更新；依用户决定不显示“估算”，记录该算法和限制，不宣称字数精度。

## Migration Plan

1. 先完成两站 P0 门槛及必要依赖/域名验证，再确定正式请求配置。禁止在门槛失败时将后续勾选为完成。
2. 编写并测试新迁移：在同一迁移事务暂存父表和相关子表数据，按外键顺序重建受约束表，再按原 ID/JSON 恢复章节、资源、进度、书签和索引。避免依赖不同池连接上的 PRAGMA；不通过删除父表触发级联而丢失数据。验证失败回滚及 foreign_key_check。
3. 注册 0003，原生 repository 增加 source 分支和统一投影；旧数据迁移为 local/in_shelf=1，现有 format/fingerprint 约束仍有效。
4. 设置迁移只新增在线额度默认值，保留所有已有阅读偏好和 comicCacheLimitMB。缓存新增 online 子目录，不把旧本地缓存当在线缓存搬迁。
5. 接通 provider、统一仓库、页面与首页；完成定向测试和真实 Windows 开发/发布验收，再启用正式来源和同步工程现状文档。
6. 升级前在隔离副本验证原库恢复路径。迁移事务失败使用原库；新版本已经写入在线数据后不做自动降级或破坏性 down-migration。回退旧应用只使用升级前备份并保留新库供恢复，不能让旧版本尝试写入不兼容数据。实际部署恢复步骤在实施验收记录中补齐。

## Open Questions

产品范围与主要方案已确认，没有待用户决定的降级入口。两站可达性、参数/编码、稳定章节证据、图片主机和来源条件属于任务 1 的强制验证项；未通过时不能按当前规格完成实现，不能作为自由选择的后续方案。

可在不改变规格和方案的情况下于实施验证补充：具体三部作品与查询样本、站点当时有效分页/响应字段、测试机的加载时间/内存实测、错误提示的详细措辞。若验证结果要求登录、验证码、另一来源或新的生产服务架构，则记录阻塞并另行取得用户决定，不能作为小细节自行替换。
